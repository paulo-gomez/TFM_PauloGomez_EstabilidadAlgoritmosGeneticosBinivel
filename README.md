# TFM_PauloGomez_EstabilidadAlgoritmosGeneticosBinivel
Repositorio del código empleado en el TFM "Estudio de la resolución práctica de problemas ΣP2-completos por medio de algoritmos genéticos binivel", por Paulo Antón Gómez Prieto.
Máster de Ingeniería Informática de la UCM, curso 2025/2026.

En este repositorio se incluyen el código Python que implementa la generación de instncias, la comprobación de resolubilidad, los algoritmos genéticos binivel y las funciones de ejecución de las diversas pruebas empleadas tanto en los procesos de diseño como en los propios experimentos de los problemas ΣP2-completos de QSAT2, la mochila binivel y el clique-coloring. Además, se incluyen las colecciones de instancias generadas y utilizadas en los experimentos para obtener los resultados que se exponen en la memoria del trabajo.

Para replicar el marco experimental de las pruebas ejecutadas, es necesario tener todos los archivos de un mismo tamaño de instancia de un problema determinado descomprimidos en el mismo directorio que el archivo con el código a ejecutar. A parte de los propios conjuntos de instancias, las colecciones de instancias también incluyen, dependiendo del problema, los archivos generales resultantes de la generación de instancias y los archivos con la información sobre el conjunto de soluciones válidas reales para ese conjunto de instancias. Ambos archivos también son necesarios para ejecutar las funciones de los experimentos. 

El producto de todos los experimentos es un archivo de resultados y un fichero de resultados parciales que va recogiendo los resultados obtenidos a medida que se van completando las ejecuciones de cada escenario.
En general, aunque el formato de las entradas varía entre las distintas funciones de ejecución de experimentos en lote (el formato específico para cada problema se indica en la definición de la función), en todas se puede indicar la cantidad y características concretas de los escenarios de las pruebas de variabilidad, así como el número de ejecuciones por instancia y otros parámetros de entrada específicos al problema sobre el que se estén realizando los experimentos. Durante la ejecución de los experimentos se irán imprimiendo por pantalla los resultados de las distintas ejecuciones, así como un reporte global del progreso de las pruebas al terminar las ejecuciones de una instancia concreta.
